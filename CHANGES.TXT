truth-table.nvim changes
========================

Unreleased
----------
- Tests: `make test-nvim` runs busted inside Neovim, through nlua, for specs
  that need an editor (`spec/*_nvim_spec.lua`); `make check` includes it and
  so requires nlua (`luarocks --lua-version 5.1 --local install nlua`). The
  pure specs still run under plain Lua and skip those files. Every check
  that was a headless script is now such a spec, with named cases that show
  both values on a failure: abbreviations, commands and keymaps, rewrite
  previews, the tutor and its replay of every lesson, the lesson pane with
  vellum, and startup (which starts a second Neovim with
  spec/startup_init.lua as its init file). Each spec file runs in a Neovim of
  its own. `make test-integration` is gone; `make check` is test, test-nvim
  and lint.
- Keymap descriptions open with their family (`Table: new`, `Rewrite: factor
  operand out`, `Apply: in place`), and the keys are registered with
  which-key family by family, so a which-key popup lists them grouped when its
  `sort` option includes "manual". The keys themselves are unchanged.
- Tutor: with vellum.nvim installed, the lesson pane shows each step
  rendered (prose wrapped to the pane's width, 100 columns at most; the title
  in a band; code in shaded panels with syntax colours), painted by the tutor
  from vellum's renderer, with no `:Vellum` preview involved. The pane is
  drawn again when its width or the colorscheme changes. Without vellum the
  pane shows the step's Markdown as before; it does the same, with one
  warning per session, when vellum raises an error or returns a highlight
  outside its line.
  - The rendered pane's filetype is `truth-table-tutor` where the Markdown
    pane's is `markdown`, and it turns off line numbers, the sign, fold and
    status columns, 'list', 'spell' and 'colorcolumn' for its window. The
    scratch pane keeps the reader's settings.
  - README and help list vellum.nvim as an optional dependency: an
    `optional = true` entry in this plugin's `dependencies`, which lazy.nvim
    acts on once vellum has a spec of its own.
  - `make test-nvim` checks the pane against a stand-in for vellum;
    TRUTH_TABLE_TEST_VELLUM=<vellum's directory> also renders every step of
    the course through the installed one.
- A step written by :TruthTableFactor is justified `distributivity
  (factoring)` and one written by :TruthTableDistribute `distributivity
  (distributing)`, where both said `distributivity`: the line now tells which
  command wrote it.
- When :TruthTableFactor or :TruthTableDistribute refuses and the other
  applies at the cursor, the refusal names it (`No neighbouring group to
  distribute Q into; to pull it out of the terms that share it, use
  :TruthTableFactor`).
- Tutor: add five lessons of Lua examples, four from a public Neovim config
  with each excerpt linked to its source at a fixed commit, and one quoted
  from Programming in Lua, section 12.1.2 (27 steps, 12 of them exercises;
  the course is now 19 lessons). Every example goes through the
  same five stages, named at the top of each step: name the checks, translate
  the code into an expression, rewrite it, put the tests back and write the
  Lua, and review the before and after side by side (counts, what the change
  buys, what it costs, a verdict).
  - 14, guard clauses: four `return false` guards turned into the single
    expression they amount to, one guard at a time.
  - 15, two negations: pulled into one with De Morgan (the cursor on the
    operator between them) and named.
  - 16, `elseif`: the condition a later branch runs under, derived in seven
    steps; a table showing the three branches cover every case once; a review
    that keeps the short form and takes the names.
  - 17, `and`/`or`: `c and x or y` against the ternary it stands in for, which
    differ in one row, and when that row can be reached.
  - 18, a dispatch on type: the branches of a function that returns nothing;
    with the rows that cannot happen dropped (a value has one type), the
    Karnaugh map shows ¬(N ∨ S) ∧ T is T, so the conditions are minimal and
    their order is free, which is what allows the nested branches to become
    guards.
- The reference lesson (now 19) lists the five stages and the rule for the
  condition each branch of an `if` runs under.
- Expressions are written back in one canonical form, in headings, previews,
  derivation steps and Karnaugh formula lines: an operand that is itself a
  binary expression is parenthesised, a run of ∧ or of ∨ is written flat, and
  no other parenthesis is written. So `a and b or c` renders as (a ∧ b) ∨ c
  where it rendered as a ∧ b ∨ c; (a ∧ b) ∧ c and a ∧ (b ∧ c) both render as
  a ∧ b ∧ c; a nested →, ⊕ or ⇔ is always marked ((a ⇔ b) ⇔ c, where it
  rendered as a ⇔ b ⇔ c); and parentheses in the source no longer survive
  rendering: ((a)) ∧ (¬(b)) is a ∧ ¬b.
- Add predicate.canonical(ast): the tree transform behind the rendering. It
  returns one tree for every grouping of an expression, with a run of ∧ or ∨
  nested to the left and paren nodes exactly where the text has parentheses.
  Rewrites return canonical trees, and rewrite.lua drops the code that
  regrouped its results and chose their parentheses.
- Add predicate.unparen, predicate.operands (the operands of a run of one
  operator, through its parentheses) and predicate.fold (a left-nested chain
  from a list of operands). rewrite.lua and karnaugh.lua use them in place of
  their own copies.
- Tutor: the distributive law is explained by what moves (distributing moves
  an operand into a group, factoring moves a shared one out), where it spoke
  of reading the law left to right or right to left.
- Tutor: expected results, law statements and the reference sheet use the
  canonical form. The lesson on connectives points out that the heading shows
  how `p or q and r` was read, and the associativity step tests the law
  through stored columns (“x ∨ y” ∨ z against x ∨ “y ∨ z”), since both
  groupings typed directly are the one expression x ∨ y ∨ z.
- Add :TruthTableSimplify (<leader>ttz): preview one collapsing law at the
  nearest match to the cursor and name it. The laws are complement (A ∨ ¬A to
  1), domination (A ∨ 1 to 1), identity (A ∨ 0 to A), idempotence, absorption
  (A ∨ A ∧ B to A, and A ∨ ¬A ∧ B to A ∨ B), reduction (A ∧ B ∨ ¬A ∧ B to B),
  each with its dual, plus a negated constant and a double negation. The
  search runs from a law involving the operand under the cursor, to one inside
  what the cursor selects, to one in a chain around it, to one anywhere.
- Every rewrite names its law. A preview ends in `| by <law>`, and
  :TruthTableApplyStep writes that after the step, with the bars of a
  derivation in one column:
      ≡ b ∧ (a ∨ ¬a)                | by distributivity
      ≡ b ∧ 1                       | by complement
  On an expression line everything from the first | on is a remark, which the
  rewrites leave alone. :TruthTableApply on a justified line adds the new law
  to its justification.
- rewrite.commute, factor, distribute, xor and de_morgan return the law's name
  as a second value. derivation.step and derivation.replace take the rewrite
  as { text, law } where they took the text; add derivation.justification.
- The predicate language reads ⊤ and ⊥ as the constants 1 and 0, so what the
  true@ and false@ abbreviations insert is now an expression (it was a parse
  error). A constant renders as typed: `a or ⊤` gives the heading a ∨ ⊤, and
  `a or 1` still gives a ∨ 1.
- The words `true` and `false` are read as ⊤ and ⊥, the way `and` is read as
  ∧, and are reserved: `:TruthTable true false` is now an expression (and a
  parse error) where it made two variables, and an existing column with either
  name is reached from an expression by its :hN reference.
- The tutor covers the laws of Boolean algebra a logic-simplification course
  lists, in 14 lessons (the lesson files after 05 are renumbered). New lesson
  6, "Constants and complements": the two spellings of the constants, the
  identity, domination and idempotence laws for `or` and `and`, duality, and
  a ∨ ¬a ≡ 1, a ∧ ¬a ≡ 0, each checked with a table. New lesson 10,
  "Absorption and reduction": absorption by table, then its second form and
  reduction derived with :TruthTableSimplify steps and taken in one move. The
  rearranging lesson gains the associative laws, the Karnaugh lesson names its
  groups as reductions, every derivation shows justified steps, and the
  reference lesson opens with a sheet of the laws under the names the
  previews give them.
- The tutor is framed around refactoring code, with examples adapted from the
  logic-exercises companion repo. Equivalence: a merge of two `return true`
  branches that the table shows to be wrong in two rows. De Morgan: a login
  check and a banner condition turned from reasons to reject into
  requirements, the second finishing with a double negation. Rearranging: a
  distributed pull-request rule factored back (∨ out of ∧), and a note on
  when commuting is safe in code. Derivations: a form condition taken through
  De Morgan twice and two double negations. Exclusive or: a retry function
  derived to (T ⊕ E) ∧ R, and its table against the `||` version. Karnaugh
  maps: the same condition, where the map finds nothing shorter. Code to
  logic: two new steps on reading a function with several returns as one
  expression (`if (c) return true; rest` is c ∨ rest, `if (c) return false;
  rest` is ¬c ∧ rest), the second on guard clauses; the reference lesson
  lists the rules.
- spec/tutor.lua evaluates every law a lesson states (`left ≡ right` in a
  fenced block of a step's text) over all values of its variables.
- :TruthTableTutor shows the course in two panes: the lesson on the left, one
  step at a time (aim, instructions, expected result), and on the right a
  scratch buffer holding that step's starting text. Each step keeps its own
  scratch, so undo stops at the starting text and work survives moving on.
- Add :TruthTableTutorNext and :TruthTableTutorPrev (]] and [[ in the tutor's
  panes) to move one step, and :TruthTableTutor {lesson} to jump to a lesson.
  :TruthTableTutor! starts the course over and rereads the lesson files.
- The course is data: one Lua table per lesson in tutor/truth-table/ (title,
  aim, steps with text, template, expect, note, solution), replacing
  tutor/truth-table-tutor.md and spec/tutor_steps.lua. spec/tutor.lua replays
  each step's solution in its scratch buffer and requires the result to equal
  the step's expectation.
- Add truth-table.tutor_page (pure Lua): render a step as the lesson pane's
  text, joining hard-wrapped prose into one line per paragraph or list item so
  the window wraps it to its own width.
- Add :TruthTableTutor: a logic course in ten lessons (tutor/truth-table-tutor.md),
  opened as a scratch copy in a new tab; every exercise runs on the tutorial's
  own lines. Running the command again returns to the copy, and ! starts a fresh
  one. spec/tutor.lua replays the exercises and checks them against the
  tutorial's expected blocks.
- Add :TruthTableXor (<leader>tto): recognise an exclusive or or an equivalence
  spelled out as two terms (¬A ∧ B ∨ A ∧ ¬B to A ⊕ B, A ∧ B ∨ ¬A ∧ ¬B to A ⇔ B,
  and the product-of-sums forms), with the cursor anywhere in either term.
- :TruthTableDeMorgan applies at the nearest match around the cursor, so a nested
  match is reachable by putting the cursor in it. From a table's data rows it
  still means the whole heading.
- Add :TruthTableFactor (<leader>ttf), :TruthTableDistribute (<leader>ttx) and
  :TruthTableCommute[!] (<leader>tts, <leader>ttS): preview a rewrite of the
  operand under the cursor, on an expression line or on a table's heading row.
- Add :TruthTableApply (<leader>tta), which replaces in place, and
  :TruthTableApplyStep (<leader>ttA), which inserts the rewrite below as a `≡`
  derivation step and moves the cursor to it. Both serve every preview, De
  Morgan included; :TruthTableDeMorganApply remains as an alias.
- On a line with `≡` separators a rewrite reads the side under the cursor and
  keeps the others. Running a pending preview's own command dismisses it; a
  different rewrite command replaces it.
- Add markdown.heading_cell: the bytes of a heading cell's content.
- Add truth-table.derivation (pure Lua): split a line into sides at ≡, replace one
  side, and build the next `≡` step line, aligned by display column.
- Add rewrite.distribute: multiply an operand into the group beside it
  (¬C ∧ (A ∨ G) to ¬C ∧ A ∨ ¬C ∧ G, and dually). A soundness spec checks every
  rewrite at every cursor byte for truth-table equivalence.
- Add rewrite.factor: pull a shared operand out of the terms of a sum or product
  (A ∧ ¬C ∨ G ∧ ¬C to ¬C ∧ (A ∨ G), and dually for ∨ inside ∧).
- Add truth-table.rewrite (pure Lua): find the operand under a cursor byte, reading
  a run of ∧, ∨, ⊕ or ⇔ as one flat chain, and commute it with its neighbour.
- Add predicate.parse_located: parse_expression's tree with a byte span on every
  node, for cursor-targeted rewrites. parse_expression's output is unchanged.
- Write the Karnaugh formula line as `target ≡ formula` (it was `target = formula`,
  which the predicate language reads as one biconditional). Add ≡ to
  truth-table.symbols and the `equiv@` abbreviation; ≡ stays outside the
  predicate language.
- Add :TruthTableKarnaugh (<leader>ttk): insert below the table a Karnaugh map
  of the column under the cursor and a minimal sum-of-products formula for it
  in the predicate language. Inputs are the shortest left-to-right run of
  columns that distinguishes every row; missing rows are don't-cares (shown as
  X). Maps are drawn for two to four inputs; the formula is always derived.
- Add truth-table.karnaugh (pure Lua: input detection, Quine-McCluskey prime
  implicants, essential primes then a budgeted exact cover with a greedy
  fallback for large functions, map layout) and markdown.format_cells for
  string-cell tables.
- Normal-mode <leader>ttn builds the table from the current line when it is
  nonblank, matching the visual mapping; a blank line still prefills
  `:TruthTable `.
- Preserve explicit setup options during automatic startup; validate abbreviation
  options before mutation and restore displaced user abbreviations on cleanup.
- Register insert-mode abbreviations for the logic symbols (and@ -> ∧, or@,
  xor@, not@, implies@, iff@, forall@, exists@, true@, false@) by default.
  setup({ abbreviations = { trigger, symbols } }) sets the input suffix and
  the per-word display symbols, or `false` disables the set; each setup()
  call replaces what the previous one registered.
- Add truth-table.symbols, one table of ASCII word plus Unicode character per
  logic symbol, shared by the predicate renderer and the abbreviations.
- Render equivalence as ⇔ in generated headings instead of =; `=` remains an
  accepted input spelling.
- Add toggled De Morgan virtual-text previews and explicit apply commands for
  whole expression lines and table headers; invalidate previews after edits.
- Separate predicate language, semantic table model, Markdown codec, and Result
  composition while preserving the string-cell core API through adapters.
- Fix expansion of F/T tables; preserve encoding through semantic operations.
- Add explicit backtick references to stored columns after dropping variables.
- Round-trip escaped pipes/backslashes; preserve grouping in generated headings.
- Validate malformed Markdown and sparse Lua arrays before transformations.
- Compatibility: toggle_cells no longer mutates input; expansion deduplicates
  headings; non-Boolean/mixed tables and empty expressions are now rejected.
- Isolate adjacent tables, ignore fenced/indented code, and preserve supported
  table indentation during edits.
- Report parser errors with source byte positions and complete Unicode characters.
- Support doubled backticks inside references to generated column headings.
- Verify plugin entry-point loading and repeated setup without which-key.
- Escape literal backticks in Markdown headings so rendered labels match stored
  reference names; verify automatic Neovim startup with a real init file.
- Add pure regression specs and headless Neovim command integration checks.

0.1.0 - 2026-06-15
------------------
- Initial extraction from the single-file Neovim config modules
  (lua/plugins/truth-table.lua + lua/truth-table-core.lua). Behavior preserved;
  structure reworked for testability:
  - Split into a pure core (lua/truth-table/core.lua, no vim dependency) and a
    vim-coupled layer (lua/truth-table/init.lua).
  - Removed vim.trim usage from the core (local trim) and made display-width
    measurement injectable: core.display_width defaults to a pure UTF-8
    codepoint count; setup() injects vim.fn.strdisplaywidth.
  - Extracted pure core.expand (predicate parse/validate/eval -> new
    headers+rows) and core.toggle_cells, so the command handlers are thin.
  - Consolidated the command handlers through a shared with_table() helper.
  - setup() registers the same commands, keymaps, and which-key labels as the
    original config.
- Added a busted spec for the core (spec/core_spec.lua), 37 cases.
- Added plugin entry point, vim help (doc/truth-table.txt), Makefile (test/lint),
  selene config, and README.
